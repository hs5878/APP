# SPEC — 연애기록 앱 MVP

- 버전: v0.3 (2026-10-03, REVIEW.md 수정안 반영)
- 상태: 초안. 근거와 대안은 `DECISIONS.md`, 저장 구조는 `DATA_MODEL.md`.
- 플랫폼: Expo(React Native) + TypeScript, iOS / Android

## 1. 제품 정의

사진만 불러오면 데이트가 카드로 자동 정리되고, AI가 한두 문장 기록을 먼저 써 주는 커플 기록 앱.
데이터는 기기에 먼저 저장되고, 언제든 일반 형식으로 통째로 가져갈 수 있다.

### 제품 원칙
1. **기기 우선**: 로컬 DB가 원본이다. 오프라인에서 조회·편집이 된다. 서버는 커플 간 동기화 중계 역할만 한다.
2. **사진은 AI에 보내지 않는다**: AI 입력은 날짜·시간대·장소명·사진 수뿐이다.
3. **확정 전 데이터는 기기 밖으로 나가지 않는다**: 후보 카드와 건너뛴 사진은 서버에 올라가지 않는다.
4. **언제든 전부 내보내기**: 사진(원본 형식), PDF, JSON으로 내려받을 수 있다.
5. **서버는 내용을 볼 수 없다**: 커플 공유 사진과 기록은 기기에서 암호화해서 올린다(종단간 암호화, D-005). 예외는 사용자가 켠 AI 초안과 장소 조회뿐이며, 이 둘도 서버에 저장하지 않는다.

## 2. MVP 범위

| # | 기능 | MVP | 비고 |
|---|---|---|---|
| F1 | 커플 연결, D-day, 기념일 | 포함 | 1인 사용 후 나중에 연결 가능 |
| F2 | 사진 자동 정리(데이트 카드) | 포함 | 후보 → 한 번 탭으로 확정 |
| F3 | AI 기록 초안 | 포함 | 끄기 가능, 실패 시 템플릿 문장 |
| F4 | 내보내기, Google Drive 백업·복원 | 포함 | 백업은 Drive 한 곳 |
| F5 | 기념일 PDF 포토북 | 포함 | 인쇄 주문 연동은 제외 |
| F6 | 앱 잠금, 알림 숨김, 저장 암호화 | 포함 | |

### MVP 제외 (v1.1 이후)
실물 포토북 주문 연동, 복구 코드와 공간 키 재발급(D-021, D-023), 상대 활동 푸시 알림(승인 요청 푸시만 포함, D-027), 음력 기념일, 홈 위젯, 대체 앱 아이콘, 동영상, 여행(여러 날) 묶음, 온디바이스 이미지 라벨링, iCloud 등 추가 백업처, 한 기기에서 여러 계정·여러 공간, 채팅·일정, 다국어, 태블릿·웹.

## 3. 기능 명세

### F1. 커플 연결과 기념일

**온보딩**: 로그인(카카오 / Apple. Android에서도 Apple 로그인 제공) → "만 14세 이상입니다" 확인 → 사귄 날 입력 → [초대 코드 만들기] 또는 [코드 입력] 또는 [나중에 연결].

**초대 코드**
- 8자리 영문 대문자+숫자, 혼동 문자(0/O, 1/I/L) 제외. 1회용, 24시간 유효. 새 코드를 만들면 이전 코드는 만료된다.
- 공유 시트로 코드와 딥링크(`app://join/CODE`)를 함께 보낸다.
- 코드 입력은 사용자당 시간당 10회로 제한한다.

**연결 승인** (D-019, D-022)
- 코드를 입력하면 바로 합류하지 않고 **연결 요청**이 간다. 초대한 사람에게 푸시 알림이 간다(D-027, 문구는 알림 숨김 설정을 따름).
- 두 사람이 함께 앱을 열어 둔 상태에서 진행한다. 초대한 사람이 요청을 열면 두 화면에 같은 6자리 확인 숫자가 뜬다. 같은지 확인하고 [승인]하면 합류한다. 요청은 24시간 유지된다.
- 승인과 함께 공간 키가 상대 기기로 안전하게 전달되고, 그 뒤부터 공유 데이터가 보인다.
- 합류자에게 기존 기록이 있으면 "내 기록도 합칠까요?"를 묻는다. [합치기]면 공간으로 옮긴다. [합치지 않기]면 내보내기를 권한 뒤 1인 공간을 지우고 합류한다(D-025).
- 사귄 날이 서로 다르면 합류 화면에서 초대한 쪽 값을 보여주고 확인받는다.

**새 기기(폰 교체)**
- 새 기기에서 로그인하면 같은 방식으로 상대 기기(또는 내 예전 기기)의 승인을 받아 공간 키를 받는다. 승인 기기에 푸시가 간다.
- 승인이 끝나면 예전 기기는 로그아웃되고 데이터가 지워진다(B4).
- 승인할 수 있는 기기가 없으면(1인 공간에서 분실, 둘 다 분실) "기기를 승인해 줄 사람이 없어요" 화면에서 [Drive 백업에서 복원] 또는 [새로 시작]을 고른다. 복원하면 새 공간으로 만들어지고 상대를 다시 초대한다(D-023).
- 연결 직후와 설정 화면에서 "Drive 백업을 켜야 두 기기를 모두 잃어도 복구돼요"를 안내한다.

**연결 해제** (D-016, D-025)
- 한쪽이 해제할 수 있다. 해제 즉시 쓰기와 동기화가 멈춘다.
- 30일 동안 두 사람 모두 서버 데이터를 읽기만 할 수 있다(빠진 상대 사진 받기, 내보내기용). 30일 뒤 서버 데이터는 삭제된다.
- 기기에서는 그 공간을 읽기 전용 "지난 기록"으로 보여준다. 홈에는 [복구 요청] [내보내기] [새로 시작]만 있다.
- 복구: 한쪽이 [복구 요청]을 하면 상대가 앱을 열 때 확인하고, 둘 다 동의하면 원래대로 돌아간다(30일 안에만).
- 새로 시작: 지난 기록을 기기에서 지우고 새 1인 공간을 만든다. 지우기 전에 내보내기를 권한다.

**D-day와 기념일**
- 홈에 `D+N`을 표시한다. 사귄 날이 1일이다(N = 오늘 − 사귄 날 + 1).
- 자동 기념일: 100일 단위(100, 200, …일)와 매 주년. 2월 29일 시작이면 평년에는 2월 28일로 계산한다.
- 사용자 기념일: 제목, 날짜, 매년 반복 여부, 알림(당일 / 1일 전 / 7일 전).
- 기념일 당일 09:00에 로컬 알림을 보낸다(설정에서 끌 수 있음).
- 알림은 롤링 예약한다. 앱 실행, 동기화 완료, 기념일·설정 변경 때마다 전부 취소하고 앞으로 60일 안의 알림만 다시 건다(최대 50개, iOS 64개 한도). 알림 숨김 문구도 이때 반영한다.

**수용 기준**
- 두 기기가 코드와 승인으로 연결되면 한쪽에서 만든 카드가 온라인 상태의 다른 기기에 30초 안에 보인다.
- commit과 다른 n_R을 공개하면 승인 기기가 요청을 거절한다(테스트).
- 승인할 기기가 없는 새 기기 로그인에서 복원·새로 시작 화면이 동작한다.
- 기념일 계산 함수가 경계값(윤년, 사귄 날 당일, 연말) 단위 테스트를 통과한다.

### F2. 사진 자동 정리

**권한**: 사진 전체 접근을 요청한다. iOS 제한 접근과 Android 14 부분 접근(선택한 사진만)이면 고른 사진만으로 동작한다. Android는 위치 메타데이터를 읽으려고 `ACCESS_MEDIA_LOCATION`을 요청한다.

**스캔** (D-007)
- 첫 스캔 범위는 사귄 날부터 오늘까지(사용자가 바꿀 수 있음).
- 1단계: `getAssetsAsync`로 촬영 시각만 받아 시간 기준으로 먼저 묶는다.
- 2단계: 3장 이상 묶음에 든 사진만 `getAssetInfoAsync`로 위치·EXIF를 읽는다. 진행률을 보여주고 중간 결과를 저장해서 앱을 껐다 켜도 이어 한다.
- `tz_offset_min`: EXIF 오프셋, 없으면 스캔 시점 기기 오프셋.
- 증분 스캔: 앱을 열 때 "마지막 스캔 날짜 − 7일"부터 다시 보고, 처리한 적 없는 사진만 처리한다(나중에 저장된 옛 사진도 잡힌다).
- 제외 대상: 스크린샷(iOS `mediaSubtypes`의 screenshot, Android는 Screenshots 앨범·파일명), 동영상, 이미 카드에 들어갔거나 건너뛴 사진.
- 원본 픽셀은 읽지 않고 메타데이터(촬영 시각, 위치)만으로 묶는다.

**묶음 규칙** (순수 함수로 구현, D-007)
1. 하루의 경계는 04:00이다(새벽 2시 사진은 전날 데이트로 묶음).
2. 같은 날 안에서 앞 사진과의 간격이 3시간 이하이면 같은 묶음이다.
3. 3장 미만인 묶음은 후보에서 뺀다.
4. 묶음 안에서 150m 안쪽으로 연달아 찍힌 사진들을 하나의 "장소 스톱"으로 만든다.
5. 오늘(04:00 경계 기준) 묶음은 후보로 띄우지 않는다. 다음 날 04:00 이후에 후보가 된다.

**후보 → 확정**
- "데이트 후보" 목록에 카드 형태로 보여준다. 사용자는 [기록하기] 또는 [건너뛰기]를 누른다. 이게 사용자가 하는 유일한 분류 작업이다.
- 기록하기를 누르면 사진 보관본을 만들고(긴 변 2048px, JPEG 85%), 장소를 조회하고, AI 초안을 요청한다.
- 이미 확정한 카드(내 것이든 상대 것이든)와 같은 날짜에 시간대가 겹치면(앞뒤 1시간 여유) 새 카드 대신 "이 카드에 추가할까요?"로 제안한다.

**같은 날 카드 합치기** (C4)
- 동기화 후 같은 날짜에 시간대가 겹치는(앞뒤 1시간) 카드가 두 개 이상이면 기록 탭 위에 "같은 데이트 같아요. 합칠까요?"를 띄운다. 두 사람이 오프라인에서 각자 확정했거나 연결 때 기록을 합친 경우다.
- 합치면 먼저 만든 카드가 남고, 다른 카드의 사진·메모를 옮긴 뒤 그 카드를 삭제한다. 요약은 남는 카드 것을 쓰고 [다시 쓰기]를 제안한다.
- 장소 스톱 합치기: 내 사진 위치가 기존 스톱 좌표(`lat_c/lng_c`)에서 150m 안이고 시간이 스톱 구간 ±30분이면 그 스톱에 넣는다. 아니면 새 스톱을 만들고 순서를 도착 시각 순으로 다시 매긴다.
- 같은 작성자의 메모가 둘 다 있으면 남는 카드 메모 뒤에 이어 붙인다. 100자를 넘으면 잘라서 확인받는다.

**카드 편집**
- 사진 추가·삭제, 다른 카드로 사진 이동, 날짜 수정, 카드 삭제, 사진 없이 직접 카드 만들기.
- 장소 스톱: 이름 바꾸기, 주변 후보 3곳 중 고르기, 직접 입력, 스톱 삭제. 장소를 바꾸면 [다시 쓰기]를 제안한다.
- 자동 장소 선택: 스톱 중심에서 가장 가까운 장소. 50m 밖이면 이름 없이 동 이름만 쓴다.

**수용 기준**
- 사진 5,000장 기준 1단계 묶음이 중급 기기에서 10초 안에 끝난다. 2단계를 포함한 전체 스캔 시간은 M3에서 측정해 기록한다.
- 카톡으로 받은 옛 사진이 다음 증분 스캔에 잡힌다.
- 묶음 함수가 자정 넘김, 04:00 경계, 3시간 간격, 위치 없는 사진, 오늘 묶음 보류 케이스 테스트를 통과한다.

### F3. AI 기록 초안

- **입력**(서버 함수가 받는 것): 날짜, 요일, 장소 스톱 목록(시간대, 장소명, 카테고리, 동 단위 지역명), 사진 수. 사진, 좌표, 사용자 이름은 보내지 않는다.
- **출력**: 한국어 1~2문장, 80자 이내. "성수동 카페 → 서울숲 산책 → 저녁 파스타"처럼 흐름형도 허용한다. 감정이나 사실을 지어내지 않는다.
- **사용자 동작**: [좋아요]로 승인 / 직접 수정 / [다시 쓰기](카드당 3회) / 한 줄 덧붙이기(두 사람이 각자 한 줄씩).
- **실패·오프라인·AI 끔**: 템플릿 문장으로 채운다. 순서는 장소명이 있으면 "장소1 · 장소2 · N곳", 동 이름만 있으면 "성수동에서", 아무것도 없으면 "사진 N장". 온라인이 되면 재시도할 수 있다.
- **설정**: [AI 초안 쓰기] 끄기, [장소 이름 찾기] 끄기. 둘 다 끄면 AI·장소 조회용으로 서버에 보내는 정보가 없다(커플 동기화는 별개).
- **제한**: 공간당 하루 30회(한국 시간 기준).

**수용 기준**: 초안 요청 페이로드에 이미지·좌표·이름 필드가 없음을 단위 테스트로 검증한다.

### F4. 내보내기와 백업

**전체 내보내기** (설정 > 내 데이터 내보내기)
- ZIP으로 만든다.
  - `photos/YYYY-MM-DD/{photo_id}.{ext}`: 내 사진은 갤러리 원본(원래 형식 그대로, JPG 또는 HEIC). 원본이 없거나 iCloud에서 받지 못하면 보관본 JPG. 상대 사진은 보관본 JPG(원본은 각자 갤러리에만 있다).
  - `records.pdf`: 카드별 날짜, 요약, 한 줄 메모, 사진 썸네일.
  - `data.json`: 전체 데이터(DATA_MODEL §6).
- 파일 경로는 처음 쓸 때 정하고 바꾸지 않는다. 카드 날짜가 바뀌어도 파일은 그대로이고, data.json의 `file`이 기준이다.
- 시작 전에 빠진 상대 사진을 먼저 받는다. 오프라인이면 "상대 사진 N장을 받아야 해요"로 막는다(D-024).
- 시작 전에 예상 크기를 보여주고, 남은 공간이 예상 크기의 2배보다 작으면 막는다. 4GB를 넘으면 기간을 나눠 여러 ZIP으로 만든다. ZIP 생성은 네이티브 모듈(`react-native-zip-archive`)로 한다.
- 기간을 고를 수 있다. 진행률 표시와 취소를 지원한다. 결과는 공유 시트로 저장한다.

**Google Drive 백업**
- Drive 계정을 연결하면(`drive.file` 범위) 내 드라이브에 보이는 "연애기록 백업" 폴더를 만든다.
- 사진은 보관본만 올린다(용량). 원본 포함은 내보내기에서만 고를 수 있다. 경로 규칙은 내보내기와 같다.
- 자동 백업: 앱 실행 때 마지막 백업 후 24시간이 지났고 Wi-Fi이면 시작한다. 사진은 한 번만 올리고(증분), 업로드는 주로 앱이 앞에 있을 때 이어 한다. 백그라운드 작업에서는 `data.json`만 올린다. `data.json` 스냅샷은 최근 7개만 남긴다.
- 백업 형식은 내보내기와 같은 일반 형식이다(앱 없이도 열림).
- 마지막 백업 시각과 실패 사유를 설정 화면에 표시한다.

**복원**: 새 기기에서 Drive를 연결하면 백업 목록에서 골라 복원한다. ID 기준으로 덮어쓰지 않고 합친다. 커플 연결 상태라면 서버 동기화로도 복구된다. 승인할 기기가 없어서 복원하는 경우는 새 공간으로 복원한다(D-023).

**데이터 약속** (설정 > 데이터 약속, 약관에도 명시)
- 서비스 종료 시 최소 3개월 전에 앱 안에서 공지한다.
- 종료 후에도 내보내기 기능이 동작하는 기간을 제공한다.
- 사진은 AI에 보내지 않는다는 점, 공유 데이터는 종단간 암호화된다는 점, 서버가 알 수 있는 것(D-020의 평문 목록)과 AI·장소 조회 때 잠깐 지나가는 정보, 서버가 행을 지우거나 예전 상태로 되돌릴 수는 있다는 한계를 표로 고지한다.

**수용 기준**
- 사진 1,000장 공간을 내보낸 ZIP을 다른 기기에서 복원하면 카드 수, 사진 수, 메모가 일치한다.
- 내보낸 data.json만으로 복원한 DB가 원본과 S 컬럼 기준으로 같다.

### F5. 기념일 포토북

- **대상**: 자동 기념일 중 직전 포토북 이후 확정된 카드가 5개 이상인 경우.
- **알림**: 기념일 14일 전 09:00 "N일 기념 포토북을 준비했어요".
- **생성 시점**: 알림 이후 처음 앱을 열 때 생성한다. 알림을 탭해서 들어왔는데 아직 없으면 그 자리에서 진행률과 함께 생성한다(백그라운드 생성은 OS가 보장하지 않음). 빠진 상대 사진은 먼저 받는다.
- **구성**: 표지(두 사람 별명, 기간, D+N) → 카드별 1~2쪽(사진 최대 4장, 요약, 한 줄 메모) → 마지막 쪽 통계(카드 수, 장소 수). 최대 40쪽이며 사진은 자동으로 고른다.
- **규격**: 200×200mm 정사각 PDF.
- **사진 크기**: 쪽 배치 크기에 맞춰 줄여 넣는다(한 장 쪽 1600px, 네 장 쪽 800px, 약 200dpi). 한 번에 다 그리지 못하면 10쪽씩 PDF를 만든 뒤 `pdf-lib`로 합친다.
- **편집**: 카드 넣기·빼기, 표지 사진 바꾸기만 지원한다.
- **출력**: PDF 저장·공유와 "인쇄 주문 안내"(외부 업체 안내 페이지 링크)만 제공한다. 업체 제휴는 v1.1.

**수용 기준**: 카드 30개짜리 포토북 생성이 중급 기기에서 30초 안에 끝나고, Android 중급 기기에서 40쪽을 만들어도 앱이 죽지 않는다.

### F6. 기본 보안

- **앱 잠금**: 6자리 PIN, 선택적으로 생체인증. 백그라운드 전환 후 잠금 시점은 즉시 / 1분 / 5분 중 고른다. 5회 틀리면 30초 대기한다. PIN 해시는 Argon2id.
- **PIN 분실**: 계정 재로그인과 기기 잠금 인증(생체 또는 기기 암호, `expo-local-authentication`)을 모두 통과하면 PIN을 재설정한다. 로컬 데이터는 그대로다(DB 키는 PIN에서 파생하지 않음).
- **앱 전환 화면 가림**: 백그라운드로 갈 때 가림 화면을 덮는다.
- **알림 내용 숨김**: 켜면 앱의 모든 알림 문구(로컬 알림과 승인 요청 푸시)가 "새 알림이 있어요"로 바뀐다. 기본값은 끔이고, 온보딩에서 한 번 물어본다.
- **저장 암호화**: SQLite는 SQLCipher로 암호화하고, 키는 SecureStore(기기 전용)에 둔다. 사진 파일은 앱 샌드박스와 OS 파일 암호화를 쓴다.
- **OS 기기 백업 제외**: Android `allowBackup=false`. iOS는 앱 데이터 폴더에 백업 제외 속성을 건다. 시작 시 DB를 열 수 없으면(키 없음) 새 설치로 보고 승인·Drive 복원 흐름으로 보낸다.
- **종단간 암호화**: 공유 사진(보관본, 썸네일)과 기록 내용은 공간 키로 기기에서 암호화한 뒤 올린다. 서버 평문으로 남는 것은 D-020 목록뿐이다. 암호 라이브러리는 libsodium만 쓴다.
- **분실 기기 차단**: 새 기기 승인이 끝나면 예전 기기는 revoke되고 그 사용자의 다른 로그인 세션이 모두 끊긴다.
- **서버**: 위에 더해 TLS, 공간 멤버만 접근하는 RLS, 비공개 버킷과 1시간짜리 서명 URL.
- **계정 삭제**(D-026): 앱 안에서 가능하다(스토어 요구사항). 커플 공간이면 먼저 연결 해제를 하고, 계정 관련 데이터는 바로, 공간 데이터는 30일 뒤 지운다. 1인 공간이면 서버 데이터를 바로 지운다. 기기 데이터도 지운다. Apple 로그인 사용자는 Apple 토큰을 폐기한다.

## 4. 화면 구조

하단 탭: **홈 / 기록 / 기념일 / 설정**

- 홈: D+N, 다음 기념일 D-n, 데이트 후보 배지, 최근 카드 3개. 해제 상태면 [복구 요청] [내보내기] [새로 시작]만.
- 기록: 월별 타임라인 → 카드 상세·편집, 데이트 후보 목록, 같은 날 카드 합치기 배너
- 기념일: 자동·사용자 기념일 목록, 포토북 미리보기
- 설정: 잠금, 알림(숨김 포함), AI·장소 사용, 백업, 내보내기, 연결 관리(사귄 날 수정, 내 별명, 연결 해제), 동기화 상태(업로드 대기·실패 재시도), 저장 공간(상대 사진 캐시 정리), 데이터 약속, 계정(로그아웃, 계정 삭제)
- 로그아웃: 기기 데이터를 지운다고 확인받은 뒤 초기화한다. 같은 기기를 다른 계정으로 쓰는 경우는 MVP에서 지원하지 않는다.
- 별도 화면: 온보딩, 연결 요청·확인 숫자, 승인할 기기 없음(복원·새로 시작), 잠금 화면, 가림 화면

## 5. 비기능 요구사항

- **암호화 성능**: 보관본 1장(약 0.5MB) 암호화·복호화가 중급 기기에서 100ms 안쪽이어야 한다. M4 첫 작업에서 측정한다.
- **오프라인**: 모든 조회·편집이 된다. 상대 사진 원본 크기 보기는 미리 받은 경우에만 오프라인에서 된다(D-024). 동기화, 연결 승인, AI, 장소 조회, 백업은 온라인이 필요하다.
- **지원 범위**: iOS 16+, Android 10+(API 29), 한국어만, 휴대폰 세로 화면만.
- **법·정책**: 개인정보처리방침, 위치정보 처리 고지, 만 14세 미만 가입 제한, 앱 내 계정 삭제. 위치기반서비스사업 신고 대상인지는 출시 전 확인한다(D-014).
